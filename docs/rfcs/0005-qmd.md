# 0005 — QMD local Markdown retrieval
Status: accepted
Date: 2026-07-23
Sponsor: Harness — needs low-token, local retrieval over project and company-brain
Markdown without preloading entire documentation sets into every agent session.

## 1. Problem & goal

Git-backed Markdown is canonical, but agents waste context by repeatedly reading
whole repositories or carrying a global documentation MCP. The desired outcome is
fast keyword-first retrieval, optional local semantic search, cited snippets, and
strict per-project/role collection isolation.

## 2. Options considered

| Option | Summary | Cost | Maturity | License |
|---|---|---|---|---|
| **QMD** | Local SQLite FTS5 + vector search + optional GGUF query expansion/reranking; CLI and MCP | Local CPU/RAM and index disk; no API tokens | Active and fast-moving | MIT |
| `rg` only | Exact text search with no index or semantic retrieval | Negligible | Mature | MIT/unlicense components |
| OpenViking only | Hierarchical context and memory for all retrieval | Higher latency/complexity for exact docs lookup | Active | AGPL-3.0 main project |

QMD complements rather than replaces `rg` or OpenViking: use `rg` for known
symbols, QMD for document discovery, and OpenViking for approved long-term memory.

## 3. Fit analysis (hard gates — Harness architecture)

- **RAM (§6):** FTS queries are light. Local embedding, expansion, and reranking
  models can consume meaningful RAM; keyword search is default, hybrid search is
  on demand, CPU parallelism is capped, and indexing is serialized against heavy
  builds.
- **Exposure (§5):** no public listener. Harness uses a local strict adapter; if
  the QMD HTTP MCP is used internally it binds to loopback only.
- **Secrets owner (§4):** no external API key. `agentops` owns index configuration
  and cache. Workers cannot edit collection configuration.
- **License:** MIT, productization-safe.
- **Backup impact:** indexes are rebuildable from Git and excluded
  from backup. Back up the pinned model manifest and Harness-owned collection
  configuration.

## 4. Upstream-verified install sketch

Verified 2026-07-23 against the official
[QMD repository and README](https://github.com/tobi/qmd) and the official
[Hermes QMD skill description](https://hermes-agent.nousresearch.com/docs/user-guide/skills/optional/research/research-qmd).

Install a pinned `@tobilu/qmd` release and pinned GGUF models under `agentops`.
Create separate project indexes plus explicitly allowed policy/company-brain
collections. Exclude secrets, raw archives, generated files, dependencies, and
other projects. Harness calls bounded `search/query/get` operations through a
strict adapter; it does not attach QMD globally to every runtime. Project files
cannot set QMD update commands because those execute shell commands before
indexing.

## 5. Recommendation

Adopt QMD as the Markdown retrieval tier. Use lexical search first, vector search
when semantics are needed, and reranking only for ambiguous/high-value queries.
Return short cited snippets and retrieve full sections progressively. Only roles
whose manifests request QMD receive its two read-only Harness tools. Record query
mode, collections, result URIs, and context bytes for token-efficiency analysis.

This is a deliberate exception to the general policy against globally attached
semantic-search MCPs. QMD is local, SQLite-backed, role-scoped, lexical-first, and
part of the approved [context specification](../specs/04-context-and-knowledge.md).
